MOSH ERP — R15 — دمج نسخة البصمة ZKTeco مع تعديلات R14
=======================================================
تاريخ التجميع: 1 أكتوبر 2026

الأساس الجديد
-------------
هذه النسخة مبنية على الحزمة التي أرسلها فريق IT باسم after fingerprint scanner.zip.
تم الحفاظ على Backend فريق IT كما هو بايتاً ببايت، بما في ذلك .env وقاعدة البيانات وstorage وvendor وملفات ZKTeco والمهاجرات والإعدادات.
قاعدة التشغيل المرفقة تحتوي جداول ZKTeco ومهاجراتها مطبقة.

ما تم دمجه
-----------
تمت إعادة تطبيق تعديلات R14 الخاصة بواجهة MOSH فوق نسخة فريق IT، مع دمج يدوي للملفين المتقاطعين api-map.json وjs/02-mosh-core-runtime-14.js حتى تبقى إضافات ZKTeco وتعديلات R14 معاً.
تم تحميل js/61-mosh-zkteco-admin.js ثم js/61-mosh-r14-system-polish.js، مع cache-busters جديدة للملفات التي تغيرت في الدمج.

التوافق
-------
- حقول رقم تسجيل ZKTeco والاستثناء موجودة في ملف الموظف.
- لوحة ZKTeco داخل HR موجودة.
- تعديلات R14 (الخطوط/المسافات/Enter/Esc/المحادثة/الصور/HR/Admin/المشتريات/اللوجستيات/الورقيات وغيرها) موجودة.
- Backend لم يُستبدل بنسخة R14 لأن R14 لم يكن يحوي تعديلات Backend؛ تم إبقاء Backend فريق IT بالكامل.
- مشروع Windows Bridge الأصلي لفريق IT محفوظ كملف منفصل بجانب حزمة MOSH النهائية، ولا يُدمج داخل مجلدي التشغيل لأن تشغيله خدمة Windows مستقلة.

الفحص
------
- Node: 38/38 ناجح.
- Browser R14/R13/R12/R10/R9: ناجح؛ تحذيرات preload = صفر؛ 62 سكربت حُمّلت مرة واحدة وبالترتيب.
- ZKTeco frontend: runtime موجود، حقول التسجيل/الاستثناء وصورة الموظف تعمل معاً بلا JavaScript errors.
- JavaScript syntax: 64 ملفاً ناجحاً.
- PHP lint: 103 ملفات مشروع ناجحة.
- SQLite quick_check: أربع قواعد = ok.
- لم تُشغّل PHPUnit الخاصة بـZKTeco في المختبر لأن PHP المتاح 8.4.23 بينما المشروع يشترط PHP >= 8.5. لم يتم تجاوز هذا الشرط داخل ملفات التسليم.

التركيب
-------
الحزمة النهائية تحتوي جذرين فقط: MOSH_LARAVEL_BACKEND وMOSH_VANILLA_FRONTEND.
طريقة محمد المعتادة: إيقاف التطبيق، الاحتفاظ بالقديم جانباً، استبدال المجلدين، ثم تشغيل التطبيق بنفس البيئة.
لا تشغّل migrate:fresh أو key:generate أو تمسح قاعدة البيانات.
