MOSH ERP — R31.1 — نسخة كاملة مصحّحة بعد استرجاع الأرشيف
=======================================================

هذه الحزمة تحتوي المشروعين كاملين:
MOSH_LARAVEL_BACKEND
MOSH_VANILLA_FRONTEND
ليست ملف HTML للمعاينة، وليست Patch.

سبب إعادة التسليم
=================
ملف MOSH_R31_FULL_IT_UPLOADS.zip السابق كان ناقصاً: 17,035,969 بايت فقط،
بلا دليل ZIP ختامي، وينتهي أثناء ملفات المكتبات قبل الوصول إلى الواجهة.
استُرجعت 3,178 مدخلاً سليماً بعد مطابقة CRC والحجم. ملفات الخلفية المعدلة
العشرة تطابق بصمات R31 المسجلة، وأُخذت بقية الملفات غير المعدلة من R30 السليمة.
أعيد بناء ملفات الواجهة الناقصة وربطها بخلفية R31 ثم إعادة الاختبارات.
لذلك هذه R31.1، وليست ادعاءً باستعادة كل بايت من الواجهة القديمة المفقودة.
لا تستخدم أرشيف R31 السابق. المرجع النهائي لهذه الحزمة R31_1_QA.json
وR31_1_CODE_MANIFEST.json وهذا الملف؛ تقارير الإصدارات السابقة تاريخية.

التعديلات الموجودة
===================
1) رفع مرفقات محادثة المهمة كأجزاء 256 كيلوبايت، حتى 25 ميغابايت للملف.
   SHA-256 مستقل يعمل على HTTP الداخلي، مع تأكيد التجميع والربط بالمهمة.
   إعادة محاولة الملف لا تنشئ مهمة جديدة. نجاح الرفع وحده لا يظهر رسالة
   في المحادثة حتى يؤكد الخادم حفظ ارتباطها. يبقى مربع الرسالة دون إعادة فتح
   نافذة أغلقها المستخدم. إيقاف الجلسة يوقف طلبات الرفع المتبقية.
2) قسم تكنولوجيا المعلومات IT بالقائمة والموظفين والمدراء والمهام:
   المعدات والعهد، حسابات الشركة، الاشتراكات، التنبيهات داخل القسم،
   ونظام مهام موش الأصلي للتوزيع والاستلام والمراجعة.
3) صلاحيتان مستقلتان من لوحة المستخدمين: viewITSecrets للإظهار والنسخ،
   وmanageITAccounts للإدارة وتحديث الأسرار. لا تكفي صفة مدير IT لكشف السر.
   كشف كلمات سر الشركة يتطلب HTTPS وتأكيد كلمة مرور حساب موش الحالي.
   حفظ سر جديد يتطلب HTTPS وصلاحية الإدارة. كلمات سر دخول موش لا تُسترجع.
   العرض يُمحى بعد 30 ثانية أو إخفاء الصفحة أو الخروج؛ الحافظة لا تُمسح تلقائياً.
4) لا تُنقل العهد القديمة تلقائياً. الأصل المرتبط بالمستودع يحافظ على
   حركاته الأصلية. إيقاف سجل الحساب أو الاشتراك في موش لا يوقفه عند مزوده
   الخارجي ولا يدفع أو يجدد الاشتراك تلقائياً. التنبيهات داخل القسم فقط.

التركيب مع حماية البيانات — للمسؤول عن السيرفر
================================================
التحديث يشمل كود الخلفية والواجهة معاً. ليس تحديث واجهة فقط مثل R30.
احتفظ بنسخة احتياطية متسقة وجرب أولاً على نسخة اختبار منفصلة.
لا تستبدل قاعدة السيرفر الحالية بقاعدة هذه الحزمة: تحتوي الحزمة بيانات
المصدر المرفوع سابقاً، وليس البيانات التي أُضيفت بعد ذلك.
أبق قاعدة العمل الحالية و.env وAPP_KEY وstorage والمرفقات وvendor
وconfig.js وإعدادات التشغيل الفعلية. دليل الكود R31_1_CODE_MANIFEST.json.
لا تغيّر كلمات المرور أو مفاتيح التشفير، ولا تستخدم migrate:fresh أو
migrate:refresh أو db:seed أو key:generate أو composer update.
لا تنقل ملف SQLite منفرداً أثناء الكتابة مع WAL/SHM؛ خذ نسخة متسقة.
المكتبات الأصلية تتطلب PHP 8.5 أو أحدث ضمن شروط Composer للمشروع.
بعد دمج الكود يحتفظ مسؤول السيرفر بإعداداته ويمسح كاش المسارات والإعدادات
والعرض بالطريقة المعتمدة عنده، ثم يعيد تحميل خدمة PHP عند الحاجة.
بعد تحديث المتصفح يظهر R31.1. لا ترفع الأرشيف أو .env أو database أو vendor
أو تقارير الكود إلى موقع عام؛ تعرّض واجهة التطبيق وpublic الخلفية فقط.

ما اختُبر وحدود النتيجة
========================
الملف الجديد فُحص كاملاً CRC بعد إغلاق ZIP وفُك فعلياً إلى مجلد آخر،
ثم طُوبقت بصمات الملفات مع مصدر التجميع. هذا يثبت اكتمال الأرشيف لا التشغيل الإنتاجي.
نجح اختبار نقل ثلاثة ملفات فعلياً إلى خادم PHP محلي، بينها 5 ميغابايت
وحد POST=1M، مع مطابقة البصمات وتجربة فقد الرد وإعادة المحاولة.
حفظ المهام وبيانات IT في اختبار المتصفح بمحاكاة API؛ ليست قاعدة SQL فعلية.
نجحت اختبارات الصلاحيات والتشفير وتجميع 25 ميغابايت على مساحة اختبار مستقلة.
توقف اختبار تشغيل Laravel عند شرط Composer: المتاح هنا PHP 8.4.24
بينما المكتبات تتطلب 8.5؛ لم تُعدل المكتبات أو يُتجاوز فحص المنصة.
لا يوجد اختبار Laravel/SQL/الجلسة/CSRF متكامل، أو دخول إلى سيرفر الشركة،
أو تجربة فعلية لحساب Meta أو جهاز البصمة. لا تعتبر الحزمة ضماناً بأن كل
وظائف النظام سليمة على بيئة الإنتاج. جلسة «لا يوجد عمل» القديمة لم تُصفّر.

قبل اعتمادها
=============
جرّب بحساب مدير وموظف محدود: حفظ سجل IT واسترجاعه بعد الخروج والدخول،
تعيين مدير لقسم IT وقسم آخر، دورة مهمة، ورفع ملفات منفردة ومتعددة ثم فتحها
بعد تحديث الصفحة. على HTTPS اختبر منح وسحب صلاحية الخزنة وكلمة مرور خاطئة.
استخدم بيانات وأسرار اختبار فقط، ولا تشغل اختبارات الحزمة على قاعدة العمل.
