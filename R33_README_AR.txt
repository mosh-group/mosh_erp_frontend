حزمة كاملة بجذرين: MOSH_LARAVEL_BACKEND وMOSH_VANILLA_FRONTEND.
ليست Patch ولا معاينة HTML. جميع ملفات R32 الأصلية محفوظة.
التغيير التشغيلي لهذه الدفعة في الواجهة فقط. ملفات الخلفية الأصلية مطابقة
حرفياً لـR32 وR31.1؛ أضيفت إلى الخلفية اختبارات وتقارير فقط.

التركيب على النظام الحالي R31.1 أو R32 — دون أوامر
=================================================
1. انتظر اكتمال أي حفظ جارٍ وأغلق صفحات موش أثناء تبديل الواجهة.
2. احتفظ بنسخة من مجلد MOSH_VANILLA_FRONTEND الحالي كاملاً للرجوع.
3. فك الحزمة الجديدة في مجلد منفصل، لا فوق مجلد التشغيل مباشرة.
4. انسخ config.js من الواجهة الحالية إلى MOSH_VANILLA_FRONTEND الجديد،
   حتى تبقى إعدادات الاتصال الحالية، خاصة إن تغيرت بعد رفع المصدر.
5. استبدل مجلد MOSH_VANILLA_FRONTEND الحالي بالجديد.
6. افتح الصفحة بتحديث كامل وتأكد من ظهور R33 بجانب الشعار.

لا تستبدل MOSH_LARAVEL_BACKEND الحالي أو قاعدة البيانات أو .env أو APP_KEY
أو storage أو المرفقات أو vendor. لا حاجة إلى migration أو composer update
أو تغيير إعدادات PHP لهذه الدفعة. الخلفية مرفقة لإبقاء المشروع كاملاً،
وليست دعوة لاستبدال قاعدة أحدث بقاعدة الحزمة القديمة.
البيانات المرفقة هي بيانات المصدر المرفوع وليست نسخة حديثة من سيرفرك.
هذه خطوات تحديث واجهة لتثبيت R31.1/R32 القائم؛ ليست تعليمات تثبيت خادم جديد.

الرجوع عند الحاجة: استعد مجلد الواجهة السابق مع config.js فقط.
تبقى الخلفية والبيانات الحالية كما هي؛ لا تسترجع قاعدة قديمة.

الإصلاحات
=========
- إصلاح التسمية الديناميكية التي كانت تعيد «مهام جارية» في قوائم الأقسام.
  «مهام قسم التصميم/التصوير/المونتاج…» و«مهام الإدارة»؛ لا تغيير للمحتويات
  أو الإحصائيات أو حالات المهام أو صلاحيات running أو «مهامي» الشخصية.
- إلغاء التهيئة الثانية غير الضرورية للوحة التسويق، وعزل واجهة السوشال
  عن لوحة العملاء، ومنع رد قديم من إبقاء واجهة السوشال فوق القسم العادي.
- تثبيت واجهة IT المعتمدة ومنع كشف القالب القديم، وعدم إعادة رسم قسم
  غادره المستخدم بسبب رد وصل متأخراً. تبويباته لا تختفي عند تحديث البيانات.
- ضبط دخول الإدارة إلى لوحة التحكم عند الضغط على القسم، حتى عند النقر
  عليه وهو مفتوح. تحديث البيانات وحده لا يعيدك من القائمة الفرعية.
- تحسين إعادة استخدام ملخص الإدارة لفترة قصيرة 15 ثانية، وتوحيد الطلب
  الجاري، وإبطال البيانات عند التحديث والحفظ وتغير الحساب، وفصل الفلاتر.
- فتح المهمة المحددة فعلياً من «مهام الإدارة»، مع زر «رجوع لمهام الإدارة».
  المهمة غير المحمّلة تُقرأ من API المصرح وتُضم إلى أساس الحفظ، لا تُنشأ
  كنسخة مكررة. مسار الاطلاع فقط يبقى منفصلاً عن مسار إدارة المهمة.
- منع رد قائمة أقدم من استبدال قائمة المهمة الأحدث، وحماية التنقّل السريع
  من إجراء مؤجل خاص بالقسم أو الحساب السابق.
- تحديث ترقيم ملفات التحميل إلى r33-nav-1 وإظهار R33 بصورة ثابتة.

==========
هذه ليست تجربة على سيرفر الشركة. لم يتاح تشغيل Laravel مع SQL والجلسة
وCSRF فعلياً هنا: Composer يطلب PHP >=8.5.0 بينما المتاح 8.4.24.
لم نغيّر vendor أو متطلبات المصدر لتجاوز ذلك، ولم نغير تشغيل خلفيتك.
لم تُختبر البصمة ZKTeco أو حساب Instagram فعلي. إعداد Meta وHTTPS لخزنة
IT وتشغيل العامل تبقى بحسب التعليمات الحالية؛ لم تُضعف الحماية لتسهيل الاختبار.
فتح شاشة محاسبة بنجاح لا يثبت صحة كل ترحيل مالي أو كل بيانات تاريخية.
جلسة «لا يوجد عمل» القديمة لم تُصفّر ولم نفترض وقت انتهائها.
أزرار إلغاء المهمة وتحويلها للأرشيف ما زالت مستبعدة وفق قرارك.
